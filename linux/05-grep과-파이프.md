# 리눅스 제로부터 #5 - grep과 파이프

> 📝 블로그 원문: [[리눅스 제로부터 #5 - grep과 파이프]](https://urigg-security.tistory.com/entry/%EB%A6%AC%EB%88%85%EC%8A%A4-%EC%A0%9C%EB%A1%9C%EB%B6%80%ED%84%B0-5-grep%EA%B3%BC-%ED%8C%8C%EC%9D%B4%ED%94%84)

이전 편에선 `less` , `head` , `tail` 로 파일 안의 내용을 읽는 방법을 공부했다. 그런데 파일이 수천 줄이라면 처음부터 끝까지 읽으며 원하는 줄을 찾는 건 불가능에 가깝다. 이번 편에선 파일에서 **원하는 줄**만 찾아내는 `grep` 과, 명령어끼리 이어 붙이는 파이프(`|`)를 다룬다.

## grep - 파일 안에서 찾기

### grep ① - grep이란 무엇인가?

`grep`은  
**G**lobal - 파일 전체에서  
**R**egular **E**xpression - 패턴을 찾아  
**P**rint - 출력해라  
는 이름처럼, 파일을 맨 윗줄부터 읽으면서 줄마다 찾는 글자가 있는지 확인하는 명령어이다. 찾는 글자가 들어있으면 그 줄을 화면에 출력하고, 없으면 넘어간다. 이걸 마지막 줄까지 반복한다. 그래서 결과는 항상 파일에 적힌 순서대로 출력된다. 아래는 `grep` 의 기본 형태이다.

```
grep 찾을단어 파일
```

2편에서 배운 명령어의 기본 구조인

```
명령어 -옵션 대상
```

구조에서, 대상 앞에 찾을 단어가 하나 더 들어간 구조이다. 이런 `grep` 을 사용할 때 꼭 알아야 할 규칙 3가지를 살펴보자.

#### 단어의 "일부"만 들어 있어도 찾는다

`grep` 은 딱 그 단어를 찾는 게 아니라, 그 글자들이 어디든 붙어 있으면 찾는다.

```
urigg@ubuntu:~$ grep log /etc/passwd
```

위 코드를 실행하면 log라는 계정은 없는데도 결과가 무수히 쏟아진다. 그 이유는 `/usr/sbin/nologin`, 그러니까 `nologin` 안에 "log"라는 글자가 들어있기 때문이다. 그래서 **찾을 단어를 구체적으로 쓰는 게** 중요하다.

#### 대문자와 소문자는 구별된다

```
grep bash /etc/passwd        //결과 나옴
grep Bash /etc/passwd        //아무것도 안 나옴
```

파일 안에는 소문자 `bash` 만 있어서 대문자 B로 시작하는 "Bash"는 없는 글자로 취급한다.

#### 띄어쓰기가 들어간 단어는 따옴표로 묶는다

```
grep "Failed password" 파일    (O)
grep Failed password 파일        (X)
```

따옴표가 없다면 리눅스는 띄어쓰기를 기준으로 나눠 읽는다. 그래서 **Failed를 찾을 단어로, password를 파일 이름으로 착각**한다. 따옴표로 감싸야 한 덩어리 단어란 걸 알려줄 수 있다.

### grep ② - 자주 사용하는 옵션

`grep` 명령어를 사용할 때 가장 자주 사용하는 옵션 4가지를 알아보겠다.

#### -i : 대소문자 무시하기

`-i` 옵션은 **ignore case**, 즉 대소문자를 무시하라는 옵션이다.

```
urigg@ubuntu:~$ grep -i BASH /etc/passwd
root:x:0:0:root:/root:/bin/bash
urigg:x:1000:1000:Daniel:/home/urigg:/bin/bash
```

대문자 `BASH` 로 입력했는데도 소문자 `bash`를 출력했다. 대소문자를 구별하는 규칙을 깨는 옵션이다. 로그 파일은 프로그램마다 적는 방식이 달라서 같은 뜻인데도 `error`, `Error`, `ERROR` 가 섞여있다. `-i` 없이 `error` 로만 찾으면 나머지 두 줄은 놓치게 된다. 보안에서 에러를 놓치는 건 치명적이기 때문에, 로그를 찾을 땐 기본으로 붙여 사용한다.

#### -n : 줄 번호 표시하기

`-n` 옵션은 **number** 라는 뜻으로, 줄 번호를 표시해 준다.

```
urigg@ubuntu:~$ grep -n bash /etc/passwd
1:root:x:0:0:root:/root:/bin/bash
48:urigg:x:1000:1000:Daniel:/home/urigg:/bin/bash
```

맨 앞 숫자와 `:` 가 **파일에서 몇 번째 줄인지**에 대한 내용이다. 원래 내용 앞에 줄 번호가 붙기만 한 거라 내용은 동일하다. 4편에서 공부한 `head`, `tail` 명령어가 사용하는 `-n` 도 number를 의미하지만, 둘은 완전히 다른 옵션이다. `grep` 명령어는 찾은 줄만 보여주고 **앞뒤 줄**은 보여주지 않는다. 하지만 로그를 볼 때는 에러 직전에 어떤 일이 있었는지 알아야 할 때가 있다. 줄 번호를 알면 4편에서 공부한 `less` 명령어로 그 위치로 가 앞뒤를 확인할 수 있다. (`less` 안에서 `48g` 처럼 줄 번호 뒤에 `g` 를 누르면 그 줄로 바로 이동한다.)

#### -v : 그 단어가 없는 줄만 보기

`-v` 옵션은 **invert** 라는 뜻으로, `찾을단어` 위치에 있는 단어가 **없는** 줄만 보여준다.

```
urigg@ubuntu:~$ grep -v nologin /etc/passwd
```

결과를 보면 `bash` 계정들 말고도 끝이 `/bin/sync`, `/bin/false` 같은 줄이 섞여 있을 수 있다. 이것들은 `nologin` 이라는 글자가 없어서 걸러지지 않은 것인데, 실제로는 역시 **로그인용이 아닌 특수 계정**이다. 로그 파일은 대부분 "정상" 기록이다. 이상한 것을 찾으려면 정상인 기록을 **빼고** 봐야 하는데, 그때 `-v`를 쓴다.

#### -r : 폴더 안의 모든 파일에서 찾기

`-r` 옵션은 **recursive** 라는 뜻으로, 3편 `rm -r`의 그 `-r` 과 같은 의미이다. 지금까지는 파일 하나를 지정했다. `-r` 을 붙이면 파일 자리에 **폴더**를 쓰고, 그 폴더 안의 모든 파일을 뒤진다.

```
urigg@ubuntu:~$ grep -r urigg /etc
/etc/passwd:urigg:x:1000:1000:Daniel:/home/urigg:/bin/bash
/etc/group:adm:x:4:syslog,urigg
grep: /etc/shadow: 허가 거부
...
```

줄 맨 앞에 **어느 파일에서 찾았는지**가 붙는다. 여러 파일을 뒤지니까 출처가 붙는 것이다. 중간에 `허가 거부` 가 나온다. 4편에서 공부한 대로 `/etc/shadow` 는 **root만 읽을 수 있는 파일**이라, 일반 사용자는 못 열어서 나오는 메시지이다.

#### 옵션 합쳐 쓰기

2편에서 배운 대로 옵션은 붙여 쓸 수 있고, **순서는 상관없다.**

```
urigg@ubuntu:~$ grep -in bash /etc/passwd      //-ni 로 써도 같음
```

\>\> 대소문자 무시하고(`-i`) + 줄 번호까지(`-n`)

```
urigg@ubuntu:~$ grep -rn urigg /etc
```

\>\> 폴더 전체를 뒤지고(`-r`) + 파일 이름 뒤에 줄 번호까지(`-n`)

## 파이프(|) - 결과 넘겨주기

### 파이프 ① - 파이프란 무엇인가?

파이프(`|`)는 **앞 명령어의 결과를 화면에 출력하지 않고, 뒤 명령어에게 재료로 넘겨주는 기호**이다.

```
명령어1 | 명령어2
```

#### 화면에는 마지막 결과만 나온다

`명령어1 | 명령어2` 를 치면 **명령어1의 결과는 화면에 나오지 않는다.** 전부 명령어2로 넘어가고, 화면에는 **맨 마지막 명령어의 결과**만 나온다. 파이프를 여러 개 이었는데 결과가 이상하면 어디서 잘못됐는지 중간 과정이 안 보여 알기 어렵다. 그래서 앞에서부터 하나씩 붙여 가며 확인하는 습관을 들이면 좋다.

```
ls /etc
ls /etc | grep conf
ls /etc | grep conf | wc -l
```

#### 명령어는 한 가지 일만 한다

리눅스 명령어는 **하나가 한 가지 일만** 하도록 만들어졌다.

- `ls` : 목록을 보여 주기만 한다.
- `grep` : 찾기만 한다.
- `head` : 앞부분 자르기만 한다.

그래서 "목록에서 찾기"처럼 두 가지 일이 섞인 작업은 한 명령어로 실행할 수 없다. 대신 파이프로 **이어 붙여서** 해결한다.

#### 파이프 뒤에는 넘겨받을 줄 아는 명령어가 온다

파이프 뒤 명령어는 **넘어온 결과를 받아서 처리할 줄 알아야 한다.** `grep`, `head`/`tail`, `less` 등이 넘겨받은 결과들을 사용하는 명령어이다. 반대로 `ls`, `cd`, `mkdir` 는 넘겨받은 결과를 쓰지 않는 명령어라서, 파이프 뒤에 붙여도 아무 의미가 없다.

### 파이프 ② - 자주 쓰는 조합

#### 명령어 결과에서 찾기

```
urigg@ubuntu:~$ ls /etc | grep conf
adduser.conf
ca-certificates.conf
...
```

위 코드를 분해해 해석해 보겠다. 먼저 `ls /etc` 가 이름 목록을 만든다. 이후 목록이 `|` 를 타고 `grep` 으로 넘어간다. `grep conf` 가 `conf` 가 들어간 이름만 남긴다. 여기서 눈여겨볼 점은 `grep` 의 형태가 바뀌었다는 것이다. `grep`의 기본 형태는 `grep 찾을단어 파일` 이었는데, 여기엔 **파일 이름**이 없다. 파일 대신 파이프로 넘어온 결과를 재료로 쓰기 때문이다. 즉 파이프 덕분에 `grep` 이 **파일이 아닌 것**, 다른 명령어의 결과에서도 찾을 수 있게 되었다. 이것이 파이프가 가진 가장 핵심적인 쓸모이다.

#### 가운데 부분만 보기

```
urigg@ubuntu:~$ head -n 20 /etc/passwd | tail -n 5
```

위 코드는 윗부분만 볼 수 있던 `head` 와 아랫부분만 볼 수 있던 `tail` 을 이어 **가운데**를 볼 수 있게 한 코드이다. 코드를 분해해 해석해 보겠다. `head -n 20` 명령어로 `/etc/passwd` 파일의 앞 20줄만 가져온다. 이후 결괏값을 `tail` 로 넘겨주고, `tail -n 5` 명령어로 그 결괏값 20줄의 마지막 5줄을 가져와 출력한다. 즉 16~20번째 줄이 출력된다. 이를 이용하면 `grep -n` 으로 "에러가 120번째 줄에 있다"는 걸 알았을 때, `head -n 125 로그파일 | tail -n 10` 처럼 사용하면 **그 주변 줄만** 잘라서 볼 수 있다.

#### 긴 결과를 스크롤하며 보기

```
urigg@ubuntu:~$ ls -l /etc | less
```

`ls -l /etc` 는 결과가 수백 줄이라 화면이 순식간에 지나간다. 4편에서 `cat` 이 긴 파일을 쏟아 버리는 문제를 `less` 로 해결했었다. **명령어 결과도 똑같이** `less` 로 넘기면 스크롤하며 천천히 볼 수 있다. 결과가 길 것 같은 명령어 뒤에 `| less` 를 붙이면 결과를 놓치지 않고, `/` 로 검색도 할 수 있어 편리해진다.

#### wc -l : 줄 수 세기

```
urigg@ubuntu:~$ grep bash /etc/passwd | wc -l
2
```

`wc` 명령어는 **word count**의 약자이고, `-l` 은 **line**, 즉 줄 수를 세라는 옵션이다. `grep` 이 찾은 2줄이 `wc -l` 로 넘어가 숫자 `2` 만 출력된다. `wc` 는 옵션 없이 쓰면 줄 수, 단어 수, 바이트 수를 한꺼번에 보여주지만, 실제로는 거의 `-l` 만 쓴다. 보안에서 **"몇 번인가?"는 중요한 판단 기준이 된다.** 로그인 실패가 한두 번이면 비밀번호를 잘못 친 사람이지만, 1분에 수백 번이면 비밀번호를 무작위로 대입하는 **공격**이 되기 때문이다.

#### 여러 개 이어 붙이기

```
urigg@ubuntu:~$ grep -v nologin /etc/passwd | grep -v false | wc -l
```

파이프는 몇 개든 이을 수 있다. 위 코드는 `nologin` 이 없는 줄만 남기고, 그 결과 중에서 `false`가 없는 줄로 한 번 더 거른 후 남은 줄을 세는 코드가 된다.

#### cat 파일 | grep 단어 는?

```
urigg@ubuntu:~$ cat /etc/passwd | grep bash
urigg@ubuntu:~$ grep bash /etc/passwd
```

위 두 코드의 **결과는 완전히 같다.** 위 코드는 `cat` 이 내용을 쏟아내면 `grep` 이 받아서 찾는다. 아래 코드는 `grep` 이 직접 파일을 열어서 찾는다. `grep` 은 원래 파일을 직접 열 수 있으니 **아래가 더 짧고 정석이다.**

## 정리

- `grep 찾을단어 파일` 은 찾는 글자가 들어 있는 줄만 출력한다. 단어의 일부만 있어도 찾고, 대소문자는 구별한다.
- `-i` 는 대소문자 무시, `-n` 은 줄 번호 표시, `-v` 는 그 단어가 없는 줄만, `-r` 은 폴더 안의 모든 파일에서 찾는다.
- 파이프(`|`)는 앞 명령어의 결과를 뒤 명령어에게 넘겨주고, 화면에는 마지막 결과만 나온다.
- 파이프 덕분에 `grep` 은 파일뿐 아니라 **다른 명령어의 결과**에서도 찾을 수 있다.
- `wc -l` 로 줄 수를 세면 "몇 번인가?"를 숫자 하나로 확인할 수 있다.

이번 편에선 `grep` 으로 원하는 줄만 찾고, 파이프로 명령어를 이어 붙여 결과를 걸러 내는 방법을 익혔다. 앞서 로그인 실패가 한두 번이면 실수지만, 1분에 수백 번이면 공격이라고 했다. 그렇다면 그 기록은 어디에 남고, 어떻게 찾아낼 수 있을까? 다음 편에선 실제 **로그 파일**을 `grep` 과 파이프로 분석해 보고, 찾은 결과를 파일로 저장하는 **리다이렉션**까지 다룬다.
