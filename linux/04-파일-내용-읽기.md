이전 편에선 리눅스 실습 환경을 구축하여 파일을 만들고, 권한을 부여해 보았다. 이번 편에선 파일 **안의 내용을 읽는 명령어**를 다룬다.

## /etc/passwd 파일

명령어를 공부하기 전, 먼저 알아야 할 것이 `/etc/passwd` 파일이다. 이 파일은 **이 시스템에 어떤 사용자 계정들이 있는지 목록을 적어둔 파일**이다. 2편에서 리눅스는 여러 사용자가 한 컴퓨터를 나눠 쓰기 위해 설계되었다는 점을 배웠었다. "누가 이 컴퓨터를 쓸 수 있는가?" 명단이 바로 `/etc/passwd` 파일이다. 한 줄이 계정 하나의 정보다.

```
root:x:0:0:root:/root:/bin/bash
urigg:x:1000:1000:URIGG:/home/urigg:/bin/bash
www-data:x:33:33:www-data:/var/www:/usr/sbin/nologin
```

파일 내부는 이렇게 생겼다. 한 줄만 뜯어 해석해 보겠다.

```
urigg : x : 1000 : 1000 : URIGG : /home/urigg : /bin/bash
  ①    ②   ③      ④      ⑤        ⑥            ⑦
```

- ① 사용자 이름 - 로그인할 때 쓰는 이름
- ② 비밀번호 자리 - `x` 는 실제 비밀번호는 여기가 아닌 `/etc/shadow`에 암호화되어 있다는 의미
- ③ UID - 사용자 번호. 컴퓨터는 이름이 아닌 사용자 번호를 통해 사람을 구분한다. **0번은 무조건 root(관리자)이다.**
- ④ GID - 소속 그룹 번호
- ⑤ 설명 - 실명 혹은 메모(비어있기도 함)
- ⑥ 홈 폴더 - 로그인하면 시작되는 위치
- ⑦ 로그인 셸 - 로그인하면 실행되는 프로그램. `/bin/bash` 면 터미널을 쓸 수 있는 계정, `/usr/sbin/nologin` 이면 로그인이 막힌 계정

### 비밀번호 자리는 왜 남아있을까?

사실 2번 자리는 **실제로 옛날에 암호화된 비밀번호가 들어있던 자리**였다. 그런데 왜 지금은 `x` 만 남아있을까?

```
urigg:Ax9f2Kd8sQ.:1000:1000:...
       ↑ 암호화된 비밀번호
```

옛날 리눅스(유닉스)에선 2번 칸에 암호화된 비밀번호가 그대로 들어있었다. 하지만 시스템의 수많은 프로그램들은 **이름과 번호**를 조회하기 위해 이 파일을 계속 열어봐야 하기에 `/etc/passwd` 는 누구나 읽을 수 있는 파일이어야 한다. 문제는 비밀번호가 여기 있으면 **암호화되어 있어도 아무나 그 암호문을 복사해 갈 수 있다**는 것이다. 해커가 그 암호문을 자기 컴퓨터로 가져가 시간 쏟아가며 크래킹 하면 결국 비밀번호를 해커가 알게 되는 것이다.

그래서 비밀번호 원본(암호문)은 `/etc/shadow` 로 옮겼다. 이 파일은 **root만 읽을 수 있게** 잠가두었다. 그리고 원래 자리인 `/etc/passwd` 의 2번 칸에는 `x` 만 남겨두었다.

그럼 왜 2번 칸은 남아있을까? 여기에는 두 가지 이유가 있다. 첫 번째는 **구조를 유지해야 하기 때문**이다. 칸을 하나 없애버리면 콜론 개수가 7개에서 6개로 바뀐다. 그럼 이 파일을 읽는 수많은 프로그램이 "3번째가 UID"라고 알고 있는데 칸이 밀려 오작동하게 된다. 그래서 **칸은 그대로 두고 내용만 `x` 로 남겨둔 것**이다. 두 번째는 **상태 표시로 활용**하기 때문이다. 이 자리를 보면 계정의 상태를 알 수 있다. 아래는 상태 표시들의 의미이다.

- `x` - 정상 (`/etc/shadow`에 비밀번호 있음)
- `*` 또는 `!` - 로그인 잠긴 계정(비밀번호로 못 들어옴)
- 비어있음(`urigg::....`) - **비밀번호 없이 로그인되는 심각한 보안 문제**

### 보안에서 /etc/passwd가 중요한 이유

`/etc/passwd`는 해커가 침투하면 가장 먼저 열어보는 파일 중 하나이다. 그 이유는 크게 세 가지다.

- **계정 목록이 다 보인다**는 특성 때문에 서버에 누구누구가 있는지 한눈에 파악이 가능하다.
- 7번째 칸으로 `/bin/bash`(로그인 가능)인 계정과 `nologin`(로그인 막힘)인 계정이 구분되어 **실제 뚫고 들어갈 수 있는 계정**을 골라낼 수 있다.
- **3번째 칸이 0인지 보아** 관리자 계정을 표적 삼을 수 있다.

때문에 보안에서 `/etc/passwd` 파일은 매우 중요하다.

## 긴 파일 보기 (less, head, tail)

2편에서 `cat` 명령어로 파일 내용을 보았다. 그러나 `cat` 명령어는 파일 내용을 **통째로 터미널에 쏟아버린다**는 점이 특징이었다. 짧은 파일이라면 괜찮지만, 긴 파일이라면 순식간에 지나가버려 읽을 수 없다는 점이 단점이었다. 그래서 긴 파일용 명령어를 알아보았다.

### less - 스크롤하며 읽기

```
less /etc/passwd
```

`less` 명령어는 파일을 **한 화면**씩 보여준다. 조작 방법은 다음과 같다.

- `space` = 한 화면씩 아래로
- `b` = 한 화면씩 위로(back)
- `up arrow, down arrow` = 한 줄씩 이동
- `G` = 맨 끝으로 점프
- `g` = 맨 처음으로 점프
- `/단어` 치고 엔터 = "단어" 검색
  - `n` = 다음 검색 결과로
  - `N` = 이전 검색 결과로
- `q` = 나가기

`less` 는 `cat` 과는 다르게 **화면 안에서 돌아다니면서 볼 수 있다**는 점이 특징이다. 게다가 **파일 전체를 메모리에 올리지 않으므로**, 수 기가바이트짜리 로그도 가볍게 열린다. `less` 명령어에 대한 재미있는 일화가 있다. 사실 `less` 보다 먼저 `more` 이라는 명령어가 있었는데 `less` 명령어가 나오면서 `more` 보다 더 낫다고 이름을 `less` 로 지었다고 한다. (진짜임)

### head/tail - 앞부분만 / 뒷부분만 읽기

```
head /etc/passwd
```
```
tail /etc/passwd
```

사용법은 간단하다. **각각 파일의 앞부분만, 뒷부분만 출력**해서 보여준다. 기본적으로 옵션을 붙이지 않으면 10줄씩 보여준다.

#### head/tail 명령어의 -n, -f 옵션

```
head -n 5 /etc/passwd
```
```
tail -n 5 /etc/passwd
```

`-n` 옵션은 number라는 의미로, `head/tail` 명령어 모두 쓸 수 있다. 옵션 뒤에 붙은 수만큼의 줄만 출력되도록 한다. 위 코드에서는 앞 5줄, 뒤 5줄이 출력될 것이다. 실제로 5줄씩 출력되는 것을 볼 수 있다.

```
tail -f 로그파일
```

`-f`는 follow라는 의미로, **실시간 감시**를 의미한다. 파일을 계속 지켜보면서, 새 줄이 추가될 때마다 바로바로 출력해 주는 옵션이다. 파일 끝에 붙는 내용을 따라가는 것이기 때문에, `tail` 명령어에만 사용할 수 있다. 이 옵션은 **로그를 실시간으로 지켜볼 때** 자주 사용한다.

## 정리

- `/etc/passwd` 는 시스템의 계정 목록 파일이고, 한 줄이 계정 하나(7칸 구조)다.
- `cat` 은 긴 파일을 통째로 쏟아내 읽기 어렵다. 그래서 긴 파일용 명령어가 필요하다.
- `less` 는 화면 안에서 스크롤하며 볼 수 있고, 큰 파일도 가볍게 열린다.
- `head`/`tail`은 앞/뒤 일부만 본다. `-n`으로 줄 수 조절.
- `tail -f`는 새 줄을 실시간으로 따라가며 로그 감시에 쓴다.

이번 편에선 **파일을 보는 방법**을 익혔다. 그러나 로그가 수천 줄이면 보는 것만으로는 부족하다. 원하는 줄만 집어 찾아야 한다. 다음 편에선 그걸 가능하게 해주는 `grep` 과, 명령어를 조립하는 파이프(`|`)를 다룬다.
