# 네트워크 첫걸음 #1 - 네트워크 개념과 구성 요소

> 📝 블로그 원문: [[네트워크 첫걸음 #1 - 네트워크 개념과 구성 요소]](https://urigg-security.tistory.com/entry/%EB%84%A4%ED%8A%B8%EC%9B%8C%ED%81%AC-%EC%B2%AB%EA%B1%B8%EC%9D%8C-1-%EB%84%A4%ED%8A%B8%EC%9B%8C%ED%81%AC-%EA%B0%9C%EB%85%90%EA%B3%BC-%EA%B5%AC%EC%84%B1-%EC%9A%94%EC%86%8C)

리눅스를 공부하면서 서버는 멀리서 원격으로 조작한다는 것을 배웠다. 공격도, 방어도, 원격 접속도 전부 컴퓨터끼리 연결되어 있기에 가능하다. 그런데 정작 **멀리 있는 컴퓨터에 어떻게 닿는지**는 모른다. 그래서 리눅스와 함께 네트워크도 첫걸음부터 정리해보기로 했다.

## 1. 네트워크란 무엇인가?

네트워크란 **두 대 이상의 기기가 서로 데이터를 주고받을 수 있게 연결된 것**이다. 내 폰이 와이파이에 연결되어 있는 것, 내 노트북이 유튜브 서버에서 영상을 받아오는 것, 멀리 있는 친구와 같이 게임을 하는 것 모두 네트워크이다.

### 네트워크에서 쓰는 기본 단어

#### 노드(Node)

네트워크에 연결된 기기 하나하나를 말한다. 폰, 노트북, 서버, 프린터 전부 노드이다.

#### 링크(Link)

노드와 노드를 잇는 연결을 말한다. 유선(랜선)일 수도 있고, 무선(와이파이)일 수도 있다.

### 왜 연결하는 것인가?

컴퓨터 한 대는 **자기가 가진 것만 쓸 수 있다.** 연결하면 다른 컴퓨터의 것도 사용할 수 있게 된다. 대표적인 이점 몇 가지를 알아보겠다.

- **정보 공유** : 서버에 있는 영상이나 글, 사진 등을 내 컴퓨터로 가져와 볼 수 있다.
- **자원 공유** : 회사에서 같은 프린터 한 대를 여러 컴퓨터가 같이 사용할 수 있다.
- **소통** : 카카오톡, 메일, 게임 멀티플레이 등 소통이 필요한 경우 네트워크가 필요하다.

## 2. 네트워크의 크기

네트워크는 얼마나 넓은 범위를 연결하느냐에 따라 나뉜다.

### LAN (Local Area Network)

좁은 지역을 잇는 네트워크이다. 보통 집, 학교, 회사 정도의 범위를 가진다. 예시로 집 공유기에 연결된 폰, 노트북, TV가 하나의 **LAN**이다. 거리가 가까워서 빠르고 안정적이고, 보통 한 사람이나 한 기관이 관리한다는 특징이 있다.

### WAN (Wide Area Network)

넓은 지역을 잇는 네트워크이다. 도시와 도시, 나라와 나라 단위의 범위를 가진다. 예시로 은행 서울 본사와 지방 지점을 잇는 네트워크를 **WAN**이라고 볼 수 있다. 거리가 멀어 LAN보다 비싸고 느리다. 보통 통신사(KT, LG유플러스, SK브로드밴드)의 망을 빌려 쓴다.

### 인터넷 (Internet)

inter(사이) + net(네트워크)라는 의미로, 네트워크를 잇는 네트워크이다. 전 세계의 수많은 LAN과 WAN이 서로 이어져 거대한 하나가 된 것을 인터넷이라고 한다.

```
[우리집 LAN] ─┐
[학교 LAN]   ─┼── 통신사 망(WAN) ── 해외 망 ── [구글 데이터센터 LAN]
[PC방 LAN]   ─┘
```

위와 같은 구조로 이어져 있다. 그래서 "인터넷에 접속한다"는 건 사실 **내 LAN에서 출발해서, 남의 LAN까지 여러 네트워크를 건너가는 것**이다.

## 3. 네트워크를 이루는 장비

데이터가 길을 찾아가려면 중간에서 안내해주는 장비가 필요하다. 핵심 3가지를 알아보겠다.

### AP (Access Point) - 네트워크에 접속하는 지점

AP는 말 그대로 기기가 네트워크에 접속하는 지점을 말한다. 보통 AP라고 하면 와이파이를 쏴주는 무선 AP를 뜻한다. AP는 유선 네트워크와 무선 기기 사이에서의 다리 역할을 한다.

```
[유선 네트워크] ──랜선── [무선 AP] ~~~와이파이 전파~~~ [폰, 노트북]
```

구조는 이렇게 생겼다. 랜선으로 들어온 데이터를 전파로 바꿔 공중에 쏴주는 것과, 반대로 무선 기기가 쏜 전파를 받아서 다시 유선 쪽으로 넘기는 일 모두 AP가 하는 일이다.

### 스위치 (Switch) - 같은 네트워크 안에서 연결

스위치는 LAN 안에서 기기끼리 데이터를 전달해 준다. 컴퓨터실 PC 여러 대가 스위치 하나에 랜선으로 꽂혀 있는 구조가 이것이다. 스위치는 데이터를 받아서 맞는 기기에게만 정확히 보내준다. 한 아파트 단지만 담당하는 택배기사라고 생각하면 쉽다.

### 라우터 (Router) - 다른 네트워크끼리 연결

라우터는 서로 다른 네트워크를 이어주고, 길을 찾아준다. 예를 들어 우리 집 LAN에서 구글까지 가려면 수십 개의 네트워크를 건너야 하는데, 라우터가 "구글은 이쪽 방향이야" 하고 다음 갈 곳을 알려주는 방식이다. 이것을 **라우팅(Routing)** 이라고 한다. 도로에서의 이정표라고 이해하면 좋다. 목적지까지 데려다주는 것이 아니라, 목적지를 보고 방향을 알려준다. 교차로마다 다음 방향만 알려주는 것이다.

### 공유기 (AP + 스위치 + 라우터)

집 공유기는 사실 위 **세 장비가 합쳐진 기계**다. 무선 AP는 선 없이 와이파이로 연결시키고, 스위치가 집 안 기기들끼리 연결시키며, 라우터가 우리 집 LAN을 바깥 인터넷과 연결하는 것이다.

## 4. 데이터가 이동하는 방법

네트워크는 데이터를 통째로 보내지 않고, 잘게 쪼개서 보낸다. 이 조각 하나를 **패킷(Packet)** 이라고 한다. 3MB짜리 사진 한 장을 보내는 과정을 뜯어보자.

```
[사진 3MB]
   ↓ 쪼개기
[조각1] [조각2] [조각3] ... [조각2000]
   ↓ 각 조각에 "받는 주소, 보내는 주소, 조각 번호" 라벨을 붙임
   ↓ 따로따로 출발 (길이 달라도 됨)
   ↓ 도착
[조각1] [조각2] ... [조각2000] → 순서대로 다시 조립
   ↓
[사진 3MB] 완성
```

### 왜 굳이 쪼개서 보낼까?

데이터를 쪼개서 보내는 데는 여러 가지 이유가 있다. 첫 번째 이유는 **데이터 이동 효율성이 오른다는 점**이다. 만약 데이터를 통째로 보내면 그 데이터가 모두 지나갈 때까지 길이 막힌다. 그러나 데이터를 쪼개서 보낸다면 여러 사람의 패킷이 섞여 길을 같이 쓸 수 있어 데이터 이동 효율성이 증가한다. 두 번째 이유는 **데이터의 복구가 쉬워진다는 점**이다. 만약 데이터를 통째로 보내다가 사라졌다면 처음부터 데이터를 다시 전송해야 한다. 그러나 패킷으로 나누게 되면 조각 하나를 잃어버려도 그 조각만 다시 보내면 되기 때문에 데이터의 복구가 쉬워진다. 마지막 세 번째 이유는 **여러 길로 나눠 갈 수 있다는 점**이다. 한 길이 막히면 라우터가 다른 길로 보낸다. 조각마다 다른 길로 가도 도착해서 조립하면 문제없기 때문이다.

### 패킷을 이루는 부분

패킷은 크게 두 부분으로 이루어져 있다. 이해하기 쉽게 택배로 비유해서 알아보겠다.

- **헤더 (Header)** : 택배의 송장 부분이다. 받는 주소, 보내는 주소, 조각 번호 같은 정보가 적혀 있다.
- **페이로드 (Payload)** : 택배 상자 안 물건이다. 실제로 보내려는 데이터 조각이다.

## 5. 프로토콜 (Protocol)

전 세계 컴퓨터는 만든 회사, 운영체제가 모두 다르다. 그렇다면 윈도우, 리눅스, iOS, 안드로이드가 어떻게 서로를 알아들을까? 그 이유는 모두가 지키기로 한 규칙, **프로토콜** 때문이다. 데이터를 어떤 형식으로 보낼지, 주소는 어떻게 적을지, 받았으면 받았다는 것을 어떻게 답할지, 조각이 사라지면 어떻게 다시 요청할지 같은 것들을 네트워크 프로토콜이 정해둔다. 아래는 프로토콜의 예시이다.

- **IP** : 주소를 붙이고 길을 찾는 약속
- **TCP/UDP** : 데이터를 어떻게 전달할지에 대한 약속
- **HTTP/HTTPS** : 웹페이지를 주고받는 약속
- **DNS** : naver.com 같은 이름을 실제 주소로 바꿔주는 약속

## 6. 클라이언트와 서버

[[리눅스 제로부터 #1 - 개념과 파일 구조]](../linux/01-개념과-파일구조.md)에서 "서버는 요청을 받으면 응답하는 컴퓨터"라고 했었다. 그 반대편에서 요청을 보내는 컴퓨터를 **클라이언트**라고 한다. 내 폰, 내 노트북의 브라우저가 모두 클라이언트다.

```
[클라이언트]  ── "이 영상 줘" (요청) ──→  [서버]
[클라이언트]  ←── 영상 데이터 (응답) ───  [서버]
```

대부분의 인터넷 서비스가 이 **요청 > 응답** 구조로 돌아간다. 클라이언트와 서버는 컴퓨터에 고정된 것이 아닌 역할이기 때문에, 같은 컴퓨터가 어떤 때는 클라이언트, 어떤 때는 서버가 될 수도 있다.

## 7. 정보보안을 공부하며 네트워크도 공부해야 하는 이유

인터넷에 연결되지 않은 컴퓨터는 해킹이 어렵다. 그런데 네트워크에 연결되는 순간, 지구 반대편 사람도 패킷을 보낼 수 있게 된다. 그래서 대부분의 해킹은 네트워크를 통해 일어난다. 방어하는 입장도 마찬가지이다. 방화벽, 침입 탐지 시스템 같은 게 전부 **어떤 패킷을 통과시키고 어떤 걸 막을지 판단**하는 장비이다. 네트워크를 모르면 공격도, 방어도 할 수 없다.

## 정리

- 네트워크는 두 대 이상의 기기가 데이터를 주고받도록 연결된 것이다.
- LAN은 좁은 지역, WAN은 넓은 지역, 인터넷은 네트워크를 연결하는 네트워크이다.
- 스위치는 같은 네트워크 안에서 전달하고, 라우터는 다른 네트워크를 잇고 길을 찾는다. AP는 기기가 네트워크에 접속하는 입구이다.
- 데이터는 효율적이고 안전하게 보내기 위해 잘게 쪼갠 **패킷**으로 전송한다.
- 프로토콜은 서로 다른 기기가 소통하기 위한 약속이다.
- 연결되었다는 것은 들어올 길이 생겼다는 것이다.

이번 편에서는 네트워크가 무엇인지, 어떤 장비들로 이루어져 있는지, 그리고 데이터가 패킷으로 쪼개져 이동한다는 것까지 알아보았다. 그런데 패킷 헤더에 적힌 "주소"는 정확히 어떻게 생겼을까? 다음 편에서는 네트워크의 주소인 **IP 주소**를 다룬다.
