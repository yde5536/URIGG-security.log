# 네트워크 첫걸음 — 완전 초보 커리큘럼

> 대상: 네트워크를 한 번도 공부해 본 적 없는 완전 초보
> 목표: 보안 공부(웹 해킹, CTF, 정보보호병, 네트워크관리사 2급)의 토대가 되는 네트워크 이해
> 원칙: **외우지 말고 본다.** 명령어로 내 컴퓨터의 네트워크를 직접 들여다본 것만 내 것이 된다.
> 작성 기준일: 2026-09-22 · **최종 갱신: 2026-10-04** (블로그 #1\~#3 발행 반영, 리눅스 편 번호 갱신)

---

## 이 커리큘럼을 쓰는 법

1. **순서대로** 진행한다. 뒤 단계는 앞 단계를 안다고 가정하고 쓰였다.
2. 네트워크는 눈에 안 보여서 개념만 읽으면 금방 잊는다. 각 단계의 **"직접 해보기"로 내 컴퓨터에서 실제 값을 확인**한다.
3. 리눅스 제로부터와 **병행**한다. 비중은 리눅스 7 : 네트워크 3 정도.
4. 각 단계가 끝나면 블로그 "네트워크 첫걸음" 한 편으로 정리한다. 단, 분량에 따라 한 단계가 두 편이 되거나 두 단계가 한 편이 될 수 있다.
5. 블로그 도입부에서 앞 편을 언급할 때는 **이미 발행한 편에서 다룬 내용만** 언급한다. 각 단계의 "앞 편과의 연결"을 참고한다.

### 준법 원칙 (반드시 지킬 것)

- 패킷 캡처(Wireshark)는 **내 컴퓨터, 내 VM, 우리 집 네트워크의 내 트래픽**에서만 한다.
- **학교 네트워크에서는 패킷 캡처나 스캔을 하지 않는다.** 학교 전산 규정 위반이 될 수 있다.
- 포트 스캔(nmap)은 **내 VM이나 내 컴퓨터(localhost)에만** 한다. 허가 없이 남의 서버를 스캔하거나 침입을 시도하면 정보통신망법 위반이 될 수 있다.
- 공격 기법은 원리를 이해하는 데까지만 공부하고, 실습은 허가된 사이트(TryHackMe 등)에서 한다.

# 0단계 — 실습 환경 준비

## 무엇을 하나
네트워크는 눈에 보이지 않는다. 그래서 **내 컴퓨터의 네트워크 정보를 보여주는 도구**를 먼저 준비한다.

## 준비물

### 1. 윈도우 명령 프롬프트 (이미 있음)
- 시작 메뉴에서 `cmd` 검색 → 명령 프롬프트 실행
- 윈도우에도 네트워크 명령어가 있다. 리눅스와 이름이 조금 다르다.

| 하는 일 | 윈도우 | 리눅스 |
|---|---|---|
| 내 IP 보기 | `ipconfig` | `ip a` |
| 자세히 보기 (MAC 주소 포함) | `ipconfig /all` | `ip a` |
| 연결 테스트 | `ping 주소` (기본 4번) | `ping -c 4 주소` (`-c` 없으면 무한 반복) |
| 경로 추적 | `tracert 주소` | `traceroute 주소` 또는 `tracepath 주소` |
| ARP 표 보기 | `arp -a` | `ip neigh` |
| DNS 조회 | `nslookup 주소` | `nslookup 주소`, `dig 주소` |
| 연결·포트 상태 | `netstat -an` | `ss -tuln` |

### 2. 우분투 VM (이미 있음)
- 집 PC의 VMware 우분투를 그대로 쓴다.
- 필요한 도구 설치:
  ```
  $ sudo apt update
  $ sudo apt install traceroute dnsutils curl nmap
  ```
  - `traceroute`: 경로 추적
  - `dnsutils`: `dig`, `nslookup` 포함
  - `curl`: 웹 요청 보내기
  - `nmap`: 포트 스캐너 (리눅스 2편 sudo 예시에 나온 그 프로그램)

### 3. Wireshark (6단계 전까지 설치)
- 네트워크를 지나가는 패킷을 **눈으로 보여주는 프로그램**. 무료.
- 윈도우: `wireshark.org`에서 설치
- 우분투 VM: `sudo apt install wireshark`
- 1편에서 배운 "패킷, 헤더, 페이로드"를 실제로 보는 도구다.

> **VMware 참고**: VMware의 기본 네트워크 방식(NAT)에서는 VM이 집 PC와 **다른 IP**를 받는다. 이상한 게 아니라 정상이다. 왜 그런지는 2단계(사설 IP와 NAT)에서 이해하게 된다. 이것 자체가 좋은 글감이다.

## 완료 기준
- 윈도우에서 `ipconfig`, VM에서 `ip a`를 쳐서 결과가 나온다.
- `ping -c 4 google.com`이 응답을 받는다.

# 2단계 — IP 주소 (#2)

## 무엇을 배우나
- IP 주소의 생김새
- 공인 IP와 사설 IP
- NAT (공유기가 하는 주소 변환)
- 특별한 주소 (127.0.0.1)
- IPv4와 IPv6

## 핵심 개념

### IP 주소란
네트워크에서 기기를 찾아가기 위한 **주소**다. 1편 패킷 헤더의 "받는 주소, 보내는 주소"가 바로 이것이다.

```
192.168.0.15
 │   │  │ │
 └───┴──┴─┴── 점(.)으로 나뉜 숫자 4개, 각각 0~255
```
- 숫자 하나는 8비트(0\~255), 4개 합쳐 **32비트**다. 이게 **IPv4**다.
- 만들 수 있는 주소는 약 43억 개(2의 32제곱). 전 세계 기기 수보다 적다. → 그래서 아래 방법들이 생겼다.

### 공인 IP와 사설 IP
| | 공인 IP | 사설 IP |
|---|---|---|
| 비유 | 아파트 단지 주소 | 단지 안의 동·호수 |
| 범위 | 전 세계에서 하나뿐 | 각자의 LAN 안에서만 유효 |
| 누가 주나 | 통신사 | 공유기 |
| 예시 | 211.xxx.xxx.xxx 등 | 192.168.0.15 |

사설 IP로 쓰기로 약속된 범위는 세 가지다.
```
10.0.0.0    ~ 10.255.255.255
172.16.0.0  ~ 172.31.255.255
192.168.0.0 ~ 192.168.255.255
```
→ 그래서 우리 집 기기들은 대부분 **192.168**로 시작한다. 옆집도, 학교도 같은 사설 IP를 쓸 수 있다. 서로 다른 LAN이라 겹쳐도 문제없다.

### NAT (Network Address Translation)
사설 IP는 인터넷에서 쓸 수 없다. 그래서 공유기가 밖으로 나가는 패킷의 보내는 주소를 **공유기의 공인 IP로 바꿔서** 내보내고, 돌아온 응답을 다시 원래 기기에게 돌려준다. 이것이 NAT다. 집 기기 여러 대가 공인 IP 하나를 **공유**하는 것이다. (그래서 이름이 "공유기")

### 특별한 주소
- `127.0.0.1` (= `localhost`): **나 자신**. 내 컴퓨터가 내 컴퓨터에게 보낼 때 쓴다. 네트워크 밖으로 나가지 않는다.
- `0.0.0.0`: 상황에 따라 "모든 주소" 또는 "아직 주소 없음". (5단계 `ss` 출력에서 다시 나온다)

### IPv6
IPv4 부족 문제의 근본 해결책. **128비트**, `2001:0db8:85a3::8a2e:0370:7334`처럼 16진수와 콜론(:)으로 쓴다. 지금은 이름과 존재만 알아둔다.

## 직접 해보기
```
윈도우 cmd
> ipconfig                    내 사설 IP (IPv4 주소 항목)

우분투 VM
$ ip a                        inet 뒤에 나오는 것이 IP
$ curl ifconfig.me            밖에서 보이는 내 공인 IP
$ ping -c 4 127.0.0.1         나 자신에게 ping
```
- 윈도우의 IP와 VM의 IP가 **다른 것**을 확인한다. (VMware도 NAT를 하기 때문)
- 집 PC와 폰의 사설 IP는 다른데, `curl ifconfig.me`(또는 폰 브라우저로 같은 사이트 접속)로 본 공인 IP는 **같다**는 걸 확인한다. → NAT를 눈으로 확인한 것

## 보안 관점
- 공인 IP는 인터넷 어디서든 보인다. 공격자가 제일 먼저 찾는 것이 목표의 IP다.
- NAT 덕분에 집 안 기기는 밖에서 직접 접근하기 어렵다. 방어 효과가 있지만, 이건 부수 효과이지 방화벽이 아니다.
- `127.0.0.1`은 웹 해킹에서도 나온다 (서버가 "자기 자신"에게 요청하게 만드는 공격, SSRF). 지금은 이름만.

## 앞 편과의 연결
- 네트워크 #1: 패킷 헤더에 "받는 주소, 보내는 주소"가 적혀 있다.
- 네트워크 #1: 공유기는 AP + 스위치 + 라우터 → 이번에 **NAT**라는 역할이 하나 더 있다는 걸 알게 된다.

## 완료 기준
- 공인 IP와 사설 IP의 차이를 설명할 수 있다.
- 192.168.x.x가 왜 여러 집에서 겹쳐도 되는지 설명할 수 있다.
- NAT가 무엇을 바꾸는지 안다.

# 3단계 — 서브넷 마스크, 게이트웨이, DHCP (#3)

## 상태
✅ **"네트워크 첫걸음 #3 - 서브넷 마스크와 DHCP"로 발행**(2026-09-29, 약 25,700자). 편을 나누자는 제안이 있었지만 한 편으로 갔다.
- 실제 목차: 1. 서브넷 마스크(우편 주소 비유, 2진수 자리값, 마스크 이름, `/24`·`/16`, `.0`·`.255`) / 2. 게이트웨이(판단 순서, **받는 주소는 바뀌지 않는다**, 공유기 = 게이트웨이, 주소 2개, "기본"의 뜻) / 3. DHCP(DORA, 주소 풀, `169.254`, 임대 기간·연장) / 4. 보안(같은 동네 = 공격 조건, 가짜 DHCP → **중간자 공격(MITM)** 이름 소개, 공유기 관리자 페이지 기본 비밀번호)
- **아래 "직접 해보기"는 블로그에서 뺐다.** 리눅스 네트워크 명령어 편에서 한다.
- 커리큘럼보다 더 다룬 것: Discover는 `0.0.0.0` → **`255.255.255.255`**로 방송(아직 동네를 몰라서 `.255`를 못 씀), Request도 방송하는 이유(서버가 여러 대일 수 있음), 임대 연장은 Request → Acknowledge 두 단계, DHCP가 나눠 주는 것 5가지(IP, 마스크, 게이트웨이, DNS 서버, 임대 기간).

## 무엇을 배우나
- 서브넷 마스크: "여기까지가 같은 동네"
- 게이트웨이: 동네 밖으로 나가는 문
- DHCP: IP를 자동으로 나눠 주는 방법

## 핵심 개념

### 서브넷 마스크
IP 주소 중 **어디까지가 네트워크(동네) 번호이고, 어디부터가 기기(집) 번호인지** 알려주는 값이다.
```
IP 주소       192.168.0.15
서브넷 마스크  255.255.255.0
              └────┬────┘ └┬┘
              네트워크 부분  기기 부분
```
- `255`인 칸은 네트워크 부분, `0`인 칸은 기기 부분.
- `192.168.0.1` \~ `192.168.0.254`는 전부 **같은 동네(같은 LAN)**다.
- 짧게 `192.168.0.0/24`라고도 쓴다. `/24`는 "앞 24비트가 네트워크 부분"이라는 뜻이다. (255.255.255.0 = 8+8+8 = 24비트)
- 기기 부분이 전부 0인 주소(`.0`)는 네트워크 자체를, 전부 1인 주소(`.255`)는 동네 전체에게 보내는 방송 주소(브로드캐스트)를 뜻한다. 그래서 기기에는 `.1` \~ `.254`를 준다.

### 기본 게이트웨이 (Default Gateway)
**같은 동네가 아닌 곳으로 보낼 때 일단 넘기는 곳**이다. 집에서는 **공유기**가 게이트웨이다. (보통 `192.168.0.1` 또는 `192.168.1.1`)
```
받는 주소가 같은 동네? ── 예 ──→ 스위치로 바로 전달
        │
       아니오
        ↓
   게이트웨이(공유기)에게 넘김 → 라우터들이 길을 찾아 감
```
1편의 스위치(같은 동네 안)와 라우터(동네 밖)가 여기서 이어진다.

### DHCP (Dynamic Host Configuration Protocol)
IP, 서브넷 마스크, 게이트웨이, DNS 서버 주소를 **자동으로 나눠 주는 프로토콜**이다. 폰을 와이파이에 연결하면 알아서 IP가 생기는 이유다. 공유기가 DHCP 서버 역할을 한다.

순서는 4단계 (앞 글자를 따서 **DORA**):
1. **D**iscover: "IP 줄 사람 있어요?" (동네 전체에 외침)
2. **O**ffer: "192.168.0.15 써도 돼" (공유기가 제안)
3. **R**equest: "그걸로 할게요"
4. **A**ck: "확정. 대신 일정 시간 동안만" (임대 기간)

## 직접 해보기
```
윈도우 cmd
> ipconfig /all
  → IPv4 주소, 서브넷 마스크, 기본 게이트웨이, DHCP 서버, 임대 시작/만료 날짜 확인

우분투 VM
$ ip a                  inet 192.168.x.x/24 ← /24가 서브넷 마스크
$ ip route              default via ○○○ ← 이 ○○○가 게이트웨이
$ ping -c 4 게이트웨이주소
```
- `ip route`의 `default via`가 무엇을 뜻하는지 스스로 설명해 본다.

## 보안 관점
- 같은 동네(같은 LAN) 안에 있다는 것 자체가 공격의 조건이 되는 경우가 많다 (4단계 ARP 스푸핑).
- **가짜 DHCP 서버**: 공격자가 DHCP 응답을 먼저 보내서 게이트웨이를 자기 컴퓨터로 알려 주면, 모든 패킷이 공격자를 거쳐 간다. 공용 와이파이가 위험한 이유 중 하나다.
- 공유기 관리 페이지(게이트웨이 주소로 접속)의 **기본 비밀번호를 안 바꾸는 것**은 대표적인 취약점이다.

## 앞 편과의 연결
- 네트워크 #1: 스위치는 같은 네트워크 안, 라우터는 다른 네트워크를 잇는다.
- 네트워크 #2: 사설 IP, 192.168로 시작하는 이유.

## 완료 기준
- `192.168.0.15/24`를 보고 같은 동네 주소 범위를 말할 수 있다.
- 게이트웨이가 무엇이고, 집에서는 무엇인지 안다.
- DHCP가 나눠 주는 정보(IP, 서브넷 마스크, 게이트웨이, DNS 서버 + 임대 기간)를 안다.
- DORA 4단계를 순서대로 말하고, Discover가 왜 `255.255.255.255`로 방송하는지 설명할 수 있다.

# 4단계 — MAC 주소와 ARP (#4)

## 무엇을 배우나
- IP 말고 주소가 하나 더 있다: MAC 주소
- 같은 LAN 안에서 실제로 배달하는 방법: ARP
- ARP 스푸핑 (첫 번째 진짜 공격 원리)

## 핵심 개념

### MAC 주소
네트워크 장치(랜카드, 와이파이 칩)에 **만들 때 붙여 나오는 고유 번호**다.
```
a4:5e:60:c2:1b:3f       16진수 2자리 × 6개 = 48비트
└──┬───┘
제조사 번호
```
| | IP 주소 | MAC 주소 |
|---|---|---|
| 비유 | 택배 받는 사람의 주소 | 받는 사람의 이름표 |
| 바뀌나 | 네트워크를 옮기면 바뀜 | 기본적으로 고정 (단, 바꿀 수 있음) |
| 쓰는 범위 | 목적지까지 전 구간 | **같은 LAN 안에서만** |
| 누가 봄 | 라우터 | 스위치 |

1편의 스위치가 "맞는 기기에게만 정확히" 보낼 수 있는 이유가 MAC 주소다. 스위치는 "몇 번 구멍에 어떤 MAC이 꽂혀 있는지" 표를 가지고 있다.

### ARP (Address Resolution Protocol)
같은 동네에 패킷을 보낼 때, IP는 아는데 MAC을 모르면 물어본다.
```
나:     "192.168.0.1 쓰는 사람 누구야? MAC 알려줘" (동네 전체에 외침)
공유기: "나야. 내 MAC은 a4:5e:60:c2:1b:3f"
나:     (표에 적어 둠 → 다음부턴 안 물어봄)
```
이 표를 **ARP 테이블**이라고 한다.

### ARP 스푸핑
ARP는 **"나야"라고 대답하는 사람을 확인 없이 믿는다.** 공격자가 "192.168.0.1은 나야, 내 MAC은 이거야"라고 거짓 대답을 보내면, 피해자는 공격자를 공유기로 믿고 패킷을 전부 공격자에게 보낸다. 공격자는 그걸 훔쳐보고 진짜 공유기로 넘겨준다. 피해자는 아무것도 눈치채지 못한다.

→ 이렇게 중간에 끼어드는 공격을 **중간자 공격(MITM, Man-In-The-Middle)**이라고 한다.

## 직접 해보기
```
윈도우 cmd
> ipconfig /all         "물리적 주소" 항목이 내 MAC
> arp -a                ARP 테이블 (IP ↔ MAC 짝)

우분투 VM
$ ip a                  link/ether 뒤가 MAC
$ ip neigh              ARP 테이블
```
- `arp -a`에서 게이트웨이 IP의 MAC을 찾아본다.
- (Wireshark 설치 후) 필터에 `arp`를 넣고 ARP 질문과 대답을 직접 본다.

> **실습 금지**: ARP 스푸핑은 원리만 이해한다. 남이 쓰는 네트워크(학교, 카페, 가족 기기 포함)에서 실행하면 불법이다. 실습은 나중에 TryHackMe 같은 허가된 환경에서만.

## 보안 관점
- 같은 LAN에 공격자가 있으면 암호화 안 된 통신은 전부 새어 나간다 → 공용 와이파이 위험, HTTPS가 중요한 이유 (9단계)
- 방어: 스위치 보안 기능, 정적 ARP 설정, 암호화 통신 사용

## 앞 편과의 연결
- 네트워크 #1: 스위치는 맞는 기기에게만 정확히 보낸다 → 그 "맞는 기기"를 구분하는 게 MAC.
- 네트워크 #3: 같은 동네인지 서브넷 마스크로 판단 → 같은 동네면 ARP로 MAC을 찾는다.
- **네트워크 #3 마치는 글의 질문**: "패킷의 받는 주소는 끝까지 유튜브 그대로인데, 내 컴퓨터는 이 패킷을 어떻게 게이트웨이에게 정확히 건네줄까? → IP 말고 또 하나의 주소가 필요하다." 4편 도입은 이 질문에 답하면서 시작한다. (답: 받는 IP는 그대로, 받는 **MAC**을 게이트웨이의 MAC으로 적는다)
- **네트워크 #3 보안**: "LAN 안은 확인 없이 믿는 약속이 많다", 가짜 DHCP와 **중간자 공격(MITM)** 이름이 이미 나왔다. ARP 스푸핑은 "같은 믿음을 노리는 두 번째 공격"으로 이어 쓰고, MITM은 새로 소개하지 말고 "3편에서 본"으로 연결한다.

## 완료 기준
- IP와 MAC의 차이를 설명할 수 있다.
- ARP가 왜 필요한지 설명할 수 있다.
- ARP 스푸핑이 가능한 이유(확인 없이 믿음)를 설명할 수 있다.

# 5단계 — 포트 (#5)

## 무엇을 배우나
- 포트가 무엇인지
- 자주 나오는 포트 번호
- 열린 포트 = 공격 표면
- 포트 스캔의 원리

## 핵심 개념

### 포트란
IP가 **건물 주소**라면 포트는 **그 건물의 호실 번호**다. 한 컴퓨터에서 웹 서버, SSH, 메일 서버가 동시에 돌 수 있는데, 도착한 패킷을 어느 프로그램에게 줄지 구분하는 번호다.
```
211.xxx.xxx.xxx:443
└──── IP ────┘ └포트┘   → "이 건물의 443호(웹 서비스)로"
```
- 범위: 0 \~ 65535
- 0 \~ 1023: **잘 알려진 포트(well-known)**. 주요 서비스용으로 약속됨
- 49152 \~ 65535: 임시 포트. 클라이언트가 요청할 때 잠깐 쓰는 번호

### 꼭 외울 포트
| 포트 | 서비스 | 한 줄 설명 |
|---|---|---|
| 20, 21 | FTP | 파일 전송 (암호화 없음) |
| 22 | SSH | 암호화된 원격 접속 (리눅스 #10) |
| 23 | Telnet | 암호화 없는 원격 접속 (쓰면 안 됨) |
| 25 | SMTP | 메일 보내기 |
| 53 | DNS | 이름 → 주소 변환 (8단계) |
| 80 | HTTP | 웹 (암호화 없음) |
| 443 | HTTPS | 웹 (암호화) |
| 3306 | MySQL | 데이터베이스 |
| 3389 | RDP | 윈도우 원격 데스크톱 |

### 열린 포트 = 문
서버에서 프로그램이 어떤 포트로 요청을 **기다리고 있으면(listen)** 그 포트는 "열려 있다". 열린 포트는 밖에서 들어올 수 있는 문이다. **필요 없는 문은 닫는 것**이 방어의 기본이다.

### 포트 스캔
어떤 포트가 열려 있는지 하나씩 두드려 보는 것. 공격의 첫 단계(정찰)이고, 방어자도 내 서버 점검에 쓴다. 대표 도구가 **nmap**이다.

## 직접 해보기
```
우분투 VM
$ ss -tuln                        내 VM에서 열려 있는 포트
$ less /etc/services              포트 번호와 서비스 이름 목록 (리눅스 #4 less)
$ grep -w 22 /etc/services        22번 포트가 뭔지 검색 (리눅스 #5 grep)
$ nmap localhost                  내 VM 자신을 스캔
```
- `ss -tuln` 출력에서 `0.0.0.0:포트`(모든 곳에서 접속 가능)와 `127.0.0.1:포트`(나만 접속 가능)의 차이를 확인한다.

> **스캔은 내 것만**: `nmap`은 `localhost`나 내 VM에만 쓴다.

## 보안 관점
- 23(Telnet), 21(FTP)이 열려 있으면 비밀번호가 암호화 없이 오간다 → 취약점
- 3306(DB), 3389(RDP)이 인터넷에 열려 있으면 무차별 대입 공격의 표적
- "열린 포트 목록 = 공격 표면(Attack Surface)"

## 앞 편과의 연결
- 네트워크 #2: IP 주소 → "건물 주소"는 알았으니, 이제 "호실".
- 리눅스 #2: `sudo apt install nmap` 예시 → 그 nmap이 이것.
- 리눅스 #4, #5: `less`, `grep`으로 `/etc/services` 읽기.

## 완료 기준
- IP와 포트의 관계를 비유로 설명할 수 있다.
- 22, 53, 80, 443이 무엇인지 안 보고 말할 수 있다.
- 열린 포트가 왜 보안상 중요한지 설명할 수 있다.

# 6단계 — TCP와 UDP (#6)

## 무엇을 배우나
- TCP: 확실하게 전달
- UDP: 빠르게 전달
- 3-way handshake (SYN, SYN-ACK, ACK)
- Wireshark로 첫 패킷 보기

## 핵심 개념

### 한눈에 비교
| | TCP | UDP |
|---|---|---|
| 비유 | 등기우편 (받았다는 확인) | 전단지 (뿌리고 끝) |
| 연결 | 먼저 연결을 맺고 시작 | 연결 없이 바로 보냄 |
| 신뢰성 | 빠진 조각은 다시 보냄, 순서 맞춤 | 확인 안 함, 빠지면 그만 |
| 속도 | 상대적으로 느림 | 빠름 |
| 쓰는 곳 | 웹(HTTP/HTTPS), SSH, 메일, 파일 전송 | DNS 조회, 실시간 게임, 영상 통화, 스트리밍 |

### 3-way handshake (TCP 연결 맺기)
TCP는 데이터를 보내기 전에 세 번 주고받으며 연결을 맺는다.
```
클라이언트                         서버
    │ ── SYN ──────────────────→  │   "연결해도 돼?"
    │ ←──────────── SYN-ACK ────  │   "응, 너도 준비됐어?"
    │ ── ACK ──────────────────→  │   "준비됐어"
    │ ═══════ 데이터 전송 시작 ═══════ │
```
- SYN = synchronize(동기화), ACK = acknowledge(확인)
- 끊을 때는 FIN을 주고받는다. 갑자기 끊을 때는 RST.

### 빠진 조각 다시 보내기
TCP는 조각마다 번호를 붙이고, 받는 쪽은 "몇 번까지 받았어"(ACK)라고 답한다. 답이 안 오면 보내는 쪽이 다시 보낸다. 1편에서 "조각 하나를 잃어버려도 그 조각만 다시 보내면 된다"고 했던 것을 실제로 해주는 게 TCP다.

## 직접 해보기
```
우분투 VM
$ sudo wireshark &              (또는 윈도우에서 Wireshark 실행)
  → 캡처할 네트워크 선택 → 캡처 시작

다른 터미널에서
$ curl http://example.com

Wireshark 필터 칸에
tcp.port == 80
```
- 목록 맨 위에서 **SYN → SYN, ACK → ACK** 세 줄을 찾는다.
- 필터를 `dns`로 바꾸면 DNS 조회가 **UDP**로 오간 것도 보인다.
- 패킷 하나를 클릭해서 헤더(주소, 포트, 번호)와 페이로드를 구분해 본다. → 1편의 "헤더 = 송장, 페이로드 = 물건"을 눈으로 확인

## 보안 관점
- **SYN 플러드 (SYN Flood)**: SYN만 잔뜩 보내고 마지막 ACK를 안 보내면, 서버는 대답을 기다리며 자원을 계속 붙잡고 있다가 결국 정상 요청을 못 받는다. 대표적인 DoS 공격.
- nmap의 기본 스캔(SYN 스캔)도 이 handshake를 이용한다. 열린 포트는 SYN-ACK, 닫힌 포트는 RST로 대답하기 때문이다.

## 앞 편과의 연결
- 네트워크 #1: 패킷, 조각 번호, 빠진 조각만 다시 보냄, 프로토콜 목록의 TCP/UDP.
- 네트워크 #5: 포트 → 포트 번호는 TCP/UDP 헤더에 들어 있다.

## 완료 기준
- TCP와 UDP 중 무엇을 쓸지, 서비스 예시로 설명할 수 있다.
- 3-way handshake 순서를 안 보고 그릴 수 있다.
- Wireshark에서 handshake 세 줄을 찾을 수 있다.

# 7단계 — 계층 모델: OSI 7계층, TCP/IP 4계층 (#7)

## 무엇을 배우나
- 네트워크를 층으로 나눠서 보는 이유
- OSI 7계층, TCP/IP 4계층
- 캡슐화 (택배 상자 안에 상자)
- 지금까지 배운 것들의 자리 찾기

## 왜 이 단계가 여기인가
처음부터 7계층을 외우면 빈 상자만 외우는 셈이다. IP, MAC, 포트, TCP를 먼저 알고 나서 보면 **"아, 그게 이 층이구나"**로 정리된다. 이 단계는 앞의 내용을 정리하는 **지도**다.

## 핵심 개념

### 계층으로 나누는 이유
각 층은 **자기 일만** 한다. 와이파이를 유선으로 바꿔도 위층(웹 브라우저)은 바꿀 필요가 없다. 문제가 생겨도 "어느 층 문제인지"로 범위를 좁힐 수 있다.

### OSI 7계층과 TCP/IP 4계층
| OSI 7계층 | 하는 일 | 지금까지 배운 것 | TCP/IP 4계층 |
|---|---|---|---|
| 7 응용 | 사용자 프로그램이 쓰는 약속 | HTTP, DNS, SSH | 응용 |
| 6 표현 | 데이터 형식, 암호화 | (TLS 일부) | 응용 |
| 5 세션 | 연결 관리 | | 응용 |
| 4 전송 | 어느 프로그램에게, 확실히/빠르게 | **TCP, UDP, 포트** | 전송 |
| 3 네트워크 | 어느 컴퓨터에게, 길 찾기 | **IP, 라우터** | 인터넷 |
| 2 데이터 링크 | 같은 LAN 안에서 전달 | **MAC, 스위치, ARP** | 네트워크 인터페이스 |
| 1 물리 | 전기 신호, 전파 | 랜선, 와이파이 전파 | 네트워크 인터페이스 |

- 외우는 법: 아래에서부터 **물데네전세표응** (물리, 데이터 링크, 네트워크, 전송, 세션, 표현, 응용)
- OSI는 설명용 교과서 모델, **실제 인터넷은 TCP/IP 모델**로 돌아간다. 시험(네트워크관리사)엔 둘 다 나온다.

### 캡슐화 (Encapsulation)
보낼 때는 위층부터 내려가며 **층마다 자기 헤더를 하나씩 붙인다.** 받는 쪽은 아래층부터 올라가며 하나씩 벗긴다.
```
[데이터]                                     응용 계층
[TCP 헤더 | 데이터]                           전송 계층 → 세그먼트
[IP 헤더 | TCP 헤더 | 데이터]                  네트워크 계층 → 패킷
[MAC 헤더 | IP 헤더 | TCP 헤더 | 데이터 | 꼬리] 데이터 링크 계층 → 프레임
→ 전기 신호 / 전파                            물리 계층 → 비트
```
택배로 치면, 물건을 작은 상자에 넣고 송장을 붙이고, 그걸 다시 큰 상자에 넣고 또 송장을 붙이는 것이다. 1편의 "헤더 + 페이로드"가 층마다 반복되는 구조다.

## 직접 해보기
- Wireshark에서 아무 TCP 패킷을 클릭한다. 아래 상세 창에 줄이 여러 개 보인다:
  ```
  Frame ...                    물리
  Ethernet II, Src: (MAC)...   데이터 링크
  Internet Protocol, Src: (IP) 네트워크
  Transmission Control Protocol, Src Port...  전송
  Hypertext Transfer Protocol  응용
  ```
- 각 줄이 몇 계층인지 표와 맞춰 본다. **캡슐화를 눈으로 보는 것이다.**

## 보안 관점
- 공격과 방어도 층으로 나눠 말한다. ARP 스푸핑은 2계층, IP 스푸핑은 3계층, SYN 플러드는 4계층, 웹 해킹은 7계층.
- 방화벽도 어느 층까지 보느냐로 나뉜다 (IP·포트만 보는 방화벽 vs 웹 요청 내용까지 보는 웹 방화벽 WAF).

## 앞 편과의 연결
- 네트워크 #1\~#6 전부. 이 편은 "지금까지 배운 것 정리" 성격으로 써도 좋다.

## 완료 기준
- OSI 7계층을 순서대로 말할 수 있다.
- IP, MAC, 포트, TCP가 각각 몇 계층인지 안다.
- 캡슐화를 택배 상자로 설명할 수 있다.

# 8단계 — DNS (#8)

## 무엇을 배우나
- 이름(naver.com)을 주소(IP)로 바꾸는 과정
- DNS 레코드 종류
- 리눅스에서 DNS 설정 파일
- DNS 스푸핑

## 핵심 개념

### DNS란
사람은 `naver.com`을 기억하고, 컴퓨터는 IP로 찾아간다. 그 사이에서 **이름 → IP로 바꿔 주는 전화번호부**가 DNS(Domain Name System)다.

### 찾아가는 순서
```
1. 내 컴퓨터가 먼저 기억(캐시)과 hosts 파일을 확인
2. 없으면 DNS 서버(보통 통신사 것)에게 "naver.com 주소 알아?"
3. 그 DNS 서버도 모르면 대신 물어보러 다님:
   루트 서버    → ".com 담당은 저쪽이야"
   .com 서버   → "naver.com 담당은 저쪽이야"
   naver.com 담당 서버 → "주소는 223.xxx.xxx.xxx야"
4. 답을 받아서 나에게 전달 (그리고 한동안 기억해 둠)
```
주소를 뒤에서부터 읽는 구조다: `.com` → `naver.com` → `www.naver.com`

### 주요 레코드
| 레코드 | 뜻 |
|---|---|
| A | 이름 → IPv4 주소 |
| AAAA | 이름 → IPv6 주소 |
| CNAME | 이름 → 다른 이름 (별명) |
| MX | 이 도메인의 메일 서버 |
| NS | 이 도메인을 담당하는 DNS 서버 |
| TXT | 메모 (소유 인증 등에 사용) |

### 리눅스의 DNS 관련 파일
- `/etc/hosts`: DNS보다 **먼저** 확인하는 수동 주소록
- `/etc/resolv.conf`: 어느 DNS 서버에게 물어볼지. 우분투에서는 `127.0.0.53`이 적혀 있는데, 우분투 안의 DNS 도우미 프로그램(systemd-resolved)에게 먼저 묻는다는 뜻이다.

## 직접 해보기
```
우분투 VM
$ nslookup naver.com
$ dig naver.com                A 레코드 (ANSWER SECTION 확인)
$ dig naver.com MX             메일 서버
$ dig +trace naver.com         루트부터 찾아가는 과정 전체
$ cat /etc/hosts
$ cat /etc/resolv.conf
```
- Wireshark 필터 `dns`로 질문과 대답 패킷을 본다. (6단계에서 본 것처럼 UDP 53번)
- 도전: `/etc/hosts`에 `127.0.0.1 test.urigg` 한 줄을 추가하고(`sudo nano /etc/hosts`) `ping -c 2 test.urigg` → 나 자신에게 간다. 실습 후 그 줄은 지운다.

## 보안 관점
- **DNS 스푸핑 / 캐시 포이즈닝**: 가짜 DNS 대답으로 `bank.com`을 공격자 서버 IP로 바꾸면, 주소창은 정상인데 가짜 사이트에 접속하게 된다.
- **hosts 파일 변조**: 악성코드가 `/etc/hosts`(윈도우도 비슷한 파일이 있음)를 바꿔 같은 효과를 낸다. 위 도전 실습이 바로 그 원리다.
- 기본 DNS는 암호화가 없어서 어떤 사이트를 조회했는지 같은 LAN에서 보인다. (그래서 DNS over HTTPS 같은 기술이 나왔다)

## 앞 편과의 연결
- 네트워크 #1: 프로토콜 목록의 DNS.
- 네트워크 #2: IP 주소. 네트워크 #5\~#6: 53번 포트, UDP.
- 리눅스 #4: `/etc/passwd`처럼 `/etc` 안의 설정 파일.

## 완료 기준
- `naver.com`이 IP로 바뀌는 과정을 순서대로 말할 수 있다.
- A, CNAME, MX 레코드가 무엇인지 안다.
- DNS 스푸핑이 왜 위험한지 설명할 수 있다.

# 9단계 — HTTP와 HTTPS (#9)

## 무엇을 배우나
- 웹이 주고받는 요청과 응답의 생김새
- 메서드, 상태 코드, 헤더, 쿠키
- HTTPS = HTTP + 암호화 (TLS)
- 스니핑과 HTTPS

## 핵심 개념

### HTTP 요청과 응답
1편의 "요청 → 응답"이 실제로는 이렇게 생긴 **텍스트**다.
```
요청 (클라이언트 → 서버)
GET /index.html HTTP/1.1          ← 메서드, 경로, 버전
Host: example.com                 ← 헤더
User-Agent: curl/8.5.0

응답 (서버 → 클라이언트)
HTTP/1.1 200 OK                   ← 상태 코드
Content-Type: text/html           ← 헤더
                                  ← 빈 줄
<html>...                         ← 본문 (페이로드)
```

### 메서드
| 메서드 | 뜻 |
|---|---|
| GET | 가져와 (페이지 보기) |
| POST | 이거 받아 (로그인, 글쓰기) |
| PUT / DELETE | 수정해 / 지워 |

### 상태 코드
| 코드 | 뜻 | 예 |
|---|---|---|
| 2xx | 성공 | 200 OK |
| 3xx | 다른 곳으로 가 | 301 주소 영구 이동 |
| 4xx | 요청한 쪽 잘못 | 403 권한 없음, 404 없음 |
| 5xx | 서버 쪽 잘못 | 500 서버 오류 |

### 쿠키와 세션
HTTP는 요청 하나하나를 **기억하지 못한다.** 그래서 로그인하면 서버가 "이 번호표 들고 다녀"라며 쿠키를 준다. 이후 요청마다 쿠키를 같이 보내서 "아까 로그인한 그 사람"임을 증명한다.

### HTTPS
HTTP를 **TLS로 암호화**한 것. 포트는 443.
- 중간에서 패킷을 훔쳐봐도 내용을 읽을 수 없다.
- **인증서**로 "이 서버가 진짜 그 사이트가 맞다"는 것도 확인한다.
- 주의: HTTPS는 "통신이 암호화됐다"는 뜻이지 "착한 사이트"라는 뜻이 아니다. 피싱 사이트도 HTTPS를 쓸 수 있다.

## 직접 해보기
```
우분투 VM
$ curl -v http://example.com       > 는 보낸 요청, < 는 받은 응답
$ curl -I https://www.naver.com    응답 헤더만
$ curl -I http://www.naver.com     http로 오면 https로 보내는 3xx 확인
```
- Wireshark에서 `http` 필터로 `http://example.com` 요청을 보면 **내용이 그대로 보인다.**
- 같은 사이트를 `https://`로 요청하면 `tls`로만 보이고 내용은 읽을 수 없다.
- → 이 두 화면을 나란히 비교하는 것이 이 편의 핵심 스크린샷이 된다.

## 보안 관점
- **스니핑**: HTTP로 로그인하면 비밀번호가 패킷에 그대로 담긴다. 4단계 ARP 스푸핑과 합쳐지면 같은 와이파이의 공격자가 읽을 수 있다.
- **쿠키 탈취**: 쿠키를 훔치면 비밀번호 없이 로그인한 척할 수 있다 (세션 하이재킹).
- 웹 해킹(XSS, SQL 인젝션 등)은 전부 이 HTTP 요청을 조작하는 일이다. → 웹 해킹 시리즈의 출발점

## 앞 편과의 연결
- 네트워크 #1: 클라이언트와 서버, 요청과 응답, 프로토콜 목록의 HTTP/HTTPS.
- 네트워크 #5\~#7: 80/443 포트, TCP, 응용 계층.

## 완료 기준
- HTTP 요청과 응답의 첫 줄을 읽을 수 있다.
- 200, 301, 404, 500의 뜻을 안다.
- HTTP와 HTTPS의 차이를 Wireshark 화면으로 설명할 수 있다.

# 10단계 — 종합: 주소창에 엔터를 누르면 (#10)

## 무엇을 하나
지금까지 배운 것을 **한 번의 웹 접속**으로 전부 엮는다. 면접 단골 질문이기도 하다.

## 전체 흐름
```
주소창에 https://www.naver.com 입력 후 엔터
 1. DNS        www.naver.com의 IP를 알아냄             (8단계)
 2. 게이트웨이  같은 동네가 아니니 공유기로 보냄         (3단계)
 3. ARP        공유기의 MAC 주소를 알아냄               (4단계)
 4. NAT        공유기가 보내는 주소를 공인 IP로 바꿈     (2단계)
 5. 라우팅      라우터들을 건너 네이버 서버까지           (1단계)
 6. TCP        443번 포트로 3-way handshake            (5~6단계)
 7. TLS        암호화 통로를 만들고 인증서 확인          (9단계)
 8. HTTP       GET 요청 → 200 응답                     (9단계)
 9. 브라우저    받은 HTML을 화면에 그림
```

## 직접 해보기
- Wireshark 캡처를 켜고 브라우저로 사이트 하나 접속 → 위 순서의 패킷을 **최대한 많이** 찾아본다 (dns → tcp handshake → tls).
- `traceroute www.naver.com` → 5번 라우팅에서 거쳐 가는 라우터 목록을 본다. (중간에 `* * *`가 나오는 건 응답을 막아 둔 라우터라 정상이다)

## 완료 기준
- 위 9단계를 안 보고 순서대로 설명할 수 있다.
- 각 단계가 몇 번째 편에서 배운 내용인지 연결할 수 있다.

# 11단계 — 네트워크 공격과 방어 기초 (#11)

## 무엇을 배우나
- 지금까지 흩어져 나온 공격을 한자리에 정리
- 방어 장비와 방법

## 공격 정리
| 공격 | 원리 | 나온 곳 |
|---|---|---|
| 스니핑 | 지나가는 패킷을 엿봄 | 4, 9단계 |
| ARP 스푸핑 | 가짜 MAC 대답으로 중간에 끼어듦 | 4단계 |
| IP 스푸핑 | 보내는 주소를 위조 | 2단계 |
| DNS 스푸핑 | 가짜 DNS 대답 | 8단계 |
| 가짜 DHCP | 게이트웨이를 공격자로 알려줌 | 3단계 (블로그 #3에서 다룸) |
| 포트 스캔 | 열린 문 찾기 (정찰) | 5단계 |
| DoS / DDoS | 요청을 쏟아부어 서비스 마비. DDoS는 여러 대가 동시에 | 6단계 (SYN 플러드) |
| 가짜 AP (Evil Twin) | 진짜와 같은 이름의 와이파이를 띄워 접속 유도 | 1단계 AP |

## 방어 정리
| 방어 | 하는 일 |
|---|---|
| 방화벽 | IP·포트 기준으로 패킷을 통과/차단 |
| IDS | 수상한 패킷을 **탐지해서 알림** |
| IPS | 수상한 패킷을 **탐지해서 막음** |
| VPN | 내 통신 전체를 암호화된 통로로 감쌈 |
| HTTPS, SSH | 통신 내용 암호화 |
| 불필요한 포트 닫기 | 공격 표면 줄이기 |

## 직접 해보기 (내 VM에서만)
```
우분투 VM
$ sudo ufw status                  우분투 기본 방화벽 상태
$ sudo ufw enable                  켜기
$ sudo ufw status verbose

집 PC에서 VM의 IP로
> nmap VM의IP                      (윈도우에 nmap을 설치했다면)
  → 방화벽을 켜기 전과 후의 결과 비교
$ sudo ufw disable                 실습 후 원래대로 (필요하면)
```

# 부록 B — 초보가 자주 헷갈리는 것

1. **스위치 vs 라우터** → 스위치는 같은 동네 안(MAC), 라우터는 동네 사이(IP)
2. **IP vs MAC** → IP는 목적지 주소(바뀜), MAC은 장치 이름표(같은 LAN 안에서만 씀)
3. **IP vs 포트** → IP는 건물, 포트는 호실
4. **TCP vs UDP** → UDP가 "나쁜" 게 아니다. 빠름이 필요한 곳에 맞는 선택이다
5. **공유기 = 라우터?** → 공유기는 라우터 + 스위치 + AP (+ NAT, DHCP)
6. **HTTPS = 안전한 사이트?** → 통신이 암호화됐다는 뜻일 뿐, 사이트가 착하다는 뜻은 아니다
7. **인터넷 = 웹?** → 인터넷은 네트워크들의 네트워크, 웹(HTTP)은 그 위에서 돌아가는 서비스 중 하나
