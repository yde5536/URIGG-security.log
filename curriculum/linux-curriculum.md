## 이 커리큘럼을 쓰는 법

1. **순서대로** 진행한다. 뒤 단계는 앞 단계를 안다고 가정하고 쓰였다.
2. 각 단계의 **"직접 해보기"를 반드시 실행**한다. 읽기만 하면 3일 뒤 다 잊는다.
3. 막히면 그 자리에서 검색한다. "리눅스 [명령어] 사용법" 으로 치면 다 나온다.
4. 하루에 한 단계씩이면 충분하다. **속도보다 매일 하는 게 중요**하다.
5. 각 단계가 끝나면 배운 걸 블로그/깃허브에 한 편씩 정리한다. 이게 복습이자 포트폴리오다.

# 0단계 — 리눅스가 대체 뭔가

## 무엇을 배우나
- 운영체제가 뭔지
- 리눅스가 왜 이렇게 많은 종류(배포판)로 나뉘는지
- 왜 서버는 대부분 리눅스인지
- 보안 하는 사람이 왜 리눅스를 알아야 하는지

## 핵심 개념

**운영체제(OS)** 는 컴퓨터 하드웨어와 사람 사이를 중개하는 프로그램이다. 윈도우, macOS, 리눅스가 대표적이다.

**리눅스 배포판(distribution)** 은 리눅스 커널(핵심)에 여러 도구를 묶어 만든 완성품이다. 우분투, 데비안, 칼리, CentOS 등 종류가 많은 이유는, 같은 엔진(커널)에 서로 다른 목적으로 부품을 조립했기 때문이다.

- **Ubuntu(우분투)**: 일반 데스크톱·서버용. 초보 친화적. **리눅스마스터 공부엔 이걸로.**
- **Kali(칼리)**: 모의해킹 전용. 해킹 도구가 미리 깔려 있음. **CTF·실습용으로 나중에.**
- 둘 다 데비안 기반이라 **명령어는 거의 똑같다.** 하나 배우면 다른 쪽도 쓴다.

**왜 서버는 리눅스인가**
1. 안정적이다 (몇 년씩 안 꺼지고 돌아감)
2. 가볍다 (화면 없이 명령어만으로 돌릴 수 있음 → 자원 절약)
3. 공짜다 (라이선스 비용 없음)
4. 원격 조작이 쉽다 (SSH로 전 세계 어디서든)
5. 자동화가 강력하다 (스크립트로 반복 작업 처리)
6. 오픈소스라 내부를 다 뜯어볼 수 있다 (보안 검증 가능)

**보안과 리눅스**: 공격 대상(서버)도 리눅스, 공격 도구(칼리)도 리눅스다. 웹 해킹, 침투 테스트, CTF, 포렌식 전부 리눅스 위에서 이뤄진다. **리눅스를 모르면 보안 실무의 문턱조차 못 넘는다.**

# 1단계 — 실습 환경 만들기

## 무엇을 배우나
- 내 컴퓨터를 건드리지 않고 리눅스를 쓰는 방법
- 초보에게 맞는 환경 고르기

## 3가지 방법 (위에서부터 추천)

### 방법 A — 브라우저 실습 사이트 (가장 추천, 설치 0)
- **아무것도 설치하지 않는다.** 브라우저에서 바로 리눅스 터미널이 열린다.
- 추천: **TryHackMe** 의 "Linux Fundamentals Part 1/2/3"
  - `tryhackme.com` 가입 → 검색창에 `Linux Fundamentals` → 시작
  - 화면 안에 리눅스가 통째로 들어있고, 뭘 잘못해도 내 PC는 무사하다.
- 추천: **OverTheWire Bandit** (11단계에서 본격 사용)
- **지금 당장 시작한다면 이 방법으로.**

### 방법 B — WSL (윈도우 사용자용, 설치 쉬움)
- 윈도우 안에서 리눅스를 돌리는 공식 기능이다.
- 설치:
  1. 윈도우 검색창에 `powershell` → 우클릭 → **관리자 권한으로 실행**
  2. 아래 입력 후 엔터
     ```powershell
     wsl --install
     ```
  3. 재부팅 → 우분투가 자동 설치됨 → 사용자 이름/비밀번호 설정
  4. 이후 시작 메뉴에서 `Ubuntu` 실행하면 터미널이 뜬다
- **장점**: 내 윈도우 파일과 연동되고, 진짜 리눅스처럼 쓸 수 있다.

### 방법 C — VirtualBox 가상머신 (제일 진짜배기, 설치 번거로움)
- 윈도우 안에 가상의 컴퓨터를 하나 통째로 만들어 우분투를 설치한다.
- 순서:
  1. `virtualbox.org` 에서 VirtualBox 설치
  2. `ubuntu.com` 에서 Ubuntu Desktop ISO 파일 다운로드
  3. VirtualBox에서 새 가상머신 생성 → ISO 연결 → 우분투 설치
  4. RAM 4GB 이상, 디스크 25GB 이상 할당 권장
- **장점**: GUI(그래픽 화면)까지 있는 완전한 리눅스. 스냅샷으로 되돌리기 가능.
- **단점**: 설치가 오래 걸리고 컴퓨터 사양을 좀 탄다.

# 2단계 — 터미널과 파일 시스템

## 무엇을 배우나
- 명령어의 기본 생김새
- 리눅스 파일 구조 (`/` 부터)
- 절대경로 vs 상대경로 (보안에서 중요!)
- 길 찾기 명령어: `pwd`, `ls`, `cd`

## 명령어의 기본 틀
```
명령어  -옵션  대상
  ls    -l   /home
```
- 명령어: 뭘 할지
- 옵션: 어떻게 할지 (`-` 또는 `--` 로 시작)
- 대상: 뭘 가지고 (생략하면 보통 현재 위치)
- 짧은 옵션은 붙여 쓴다: `-l -a` = `-la`

## 파일 시스템 구조

윈도우는 `C:`, `D:` 드라이브로 나뉘지만, 리눅스는 **`/`(루트) 하나에서 모든 게 뻗어나가는 나무** 구조다.

```
/
├── bin      실행 명령어들
├── etc      설정 파일들 (중요!)
├── home     사용자 개인 폴더 (/home/daeul)
├── root     root 관리자 전용 폴더
├── var      로그, 웹서버 파일 등 (로그 분석 시 중요)
├── tmp      임시 파일
└── usr      설치된 프로그램
```

- **`/etc`**: 시스템 설정이 모여있다. 공격자도 방어자도 여길 본다.
- **`/var/log`**: 로그가 쌓인다. 침해사고 분석의 출발점.
- **`/home`**: 개인 파일, SSH 키가 여기 산다.

## 경로 (path) — 보안에서 특히 중요

**절대경로**: `/` 부터 전부 적는 방식. 어디서 실행하든 같은 곳을 가리킴.
```
/home/daeul/문서/일기.txt
```

**상대경로**: 지금 있는 위치 기준.
```
문서/일기.txt      (현재 폴더 아래 문서 폴더)
./일기.txt          (. = 현재 폴더)
../사진             (.. = 한 단계 위 폴더)
```

> **왜 보안에서 중요한가**: `../` 를 악용해 허용되지 않은 상위 폴더로 빠져나가는 공격이 **경로 순회(Path Traversal)** 다. 예: `../../etc/passwd` 로 시스템 계정 파일을 훔쳐보기. 이 개념을 지금 확실히 잡아두면 나중에 웹 취약점 이해가 쉽다.

## 핵심 명령어 3개

### pwd — 나 지금 어디야
```
$ pwd
/home/daeul
```
길 잃었을 때 치는 명령어.

### ls — 여기 뭐 있어
```
$ ls              이름만
$ ls -l           자세히 (권한, 주인, 크기, 시각)
$ ls -a           숨김 파일까지 (.으로 시작하는 것들)
$ ls -la          둘 다
$ ls -lh          크기를 사람이 읽기 쉽게 (K, M, G)
```
`ls -l` 결과 읽는 법:
```
-rw-r--r-- 1 daeul daeul 1024 9월 20 05:30 일기.txt
└────┬───┘   └─┬─┘ └─┬─┘ └┬─┘              └──┬──┘
   권한       주인   그룹  크기               이름
```
맨 앞 글자: `-`=파일, `d`=폴더, `l`=링크

```

$ cp -r 원본폴더 새폴더           폴더 통째로 (-r = recursive)
```

> 삭제 전 `ls` 로 지울 대상을 반드시 확인하는 습관을 들일 것.

# 4단계 — 권한 (보안의 핵심 중 핵심)

## 무엇을 배우나
- 리눅스 권한 체계 (rwx)
- 숫자 권한 (chmod 777의 정체)
- `chmod`, `chown`

## 왜 중요한가
권한은 **리눅스 보안의 근간**이다. "누가 이 파일을 읽고/쓰고/실행할 수 있는가"를 정하는 것이고, 잘못된 권한 설정이 곧 취약점이 된다. 이 단계는 특히 꼼꼼히.

## rwx 이해하기

`ls -l` 을 치면 맨 앞에 이런 게 나온다:
```
-rwxr-xr--
```
이걸 4덩어리로 쪼갠다:
```
-    rwx    r-x    r--
│    └┬┘    └┬┘    └┬┘
종류  주인   그룹   나머지
```
- **r** (read, 읽기) = 4
- **w** (write, 쓰기) = 2
- **x** (execute, 실행) = 1
- **-** = 권한 없음

각 덩어리를 숫자로 더한다:
```
rwx = 4+2+1 = 7
r-x = 4+0+1 = 5
r-- = 4+0+0 = 4
→ 754
```

**그 유명한 `777`** = `rwxrwxrwx` = 모두가 모든 걸 할 수 있음 = **보안상 최악.** 초보가 문제 생기면 `chmod 777` 로 때우는데, 이건 문을 활짝 열어두는 짓이다. 하지 말 것.

**자주 쓰는 권한값**
| 값 | 의미 | 용도 |
|---|---|---|
| 644 | rw-r--r-- | 일반 파일 (주인만 수정) |
| 755 | rwxr-xr-x | 실행 파일, 폴더 |
| 600 | rw------- | 비밀 파일 (주인만, SSH 키!) |
| 700 | rwx------ | 주인 전용 폴더 |

## chmod — 권한 바꾸기

**숫자 방식**
```
$ chmod 644 파일.txt
$ chmod 755 스크립트.sh
$ chmod 600 secret.key
```

**기호 방식**
```
$ chmod +x 스크립트.sh      실행 권한 추가 (모두에게)
$ chmod u+x 파일             주인(u)에게 실행 권한
$ chmod g-w 파일             그룹(g)에서 쓰기 제거
$ chmod o-r 파일             나머지(o)에서 읽기 제거
```
- u=user(주인), g=group, o=other, a=all
- +추가, -제거

## chown — 주인 바꾸기 (보통 sudo 필요)
```
$ sudo chown daeul 파일.txt          주인 변경
$ sudo chown daeul:daeul 파일.txt     주인:그룹 변경
```

## 직접 해보기
```
$ cd ~/linux-practice
$ touch permtest.txt
$ ls -l permtest.txt          현재 권한 확인
$ chmod 600 permtest.txt
$ ls -l permtest.txt          rw------- 로 바뀜 확인
$ chmod 755 permtest.txt
$ ls -l permtest.txt          rwxr-xr-x 확인
$ chmod u-x permtest.txt
$ ls -l permtest.txt          주인 x가 빠짐 확인
```
숫자를 바꿔가며 `ls -l` 로 결과를 확인하는 걸 5번 이상 반복할 것. 이게 감을 잡는 유일한 길이다.

## 완료 기준
- rwx를 숫자로, 숫자를 rwx로 서로 변환할 수 있다 (예: 640 ↔ rw-r-----)
- `chmod 600` 이 왜 SSH 키에 필요한지 설명할 수 있다
- `777` 이 왜 위험한지 안다

# 5단계 — 사용자와 관리자

## 무엇을 배우나
- 일반 사용자 vs root
- `sudo` 의 원리
- 왜 평소엔 root로 안 쓰는가 (이것 자체가 방어다)

## 개념

**일반 사용자**: 자기 홈 폴더(`/home/이름`) 안에서만 자유롭다. 시스템 전체는 못 건드린다.

**root**: 최고 관리자. 뭐든 할 수 있다. 그래서 위험하다.

**sudo** (superuser do): 일반 사용자로 지내다가, 관리자 권한이 필요한 **그 한 줄만** 빌려 쓰는 방법.
```
$ apt install nmap
권한 없음 (에러)

$ sudo apt install nmap
[sudo] 암호: ****
설치 시작...
```

## 왜 항상 root로 안 쓰나
1. **실수가 치명적**: 오타 하나로 시스템이 날아간다
2. **해킹당하면 즉시 전부 뺏김**: 일반 계정이면 공격자가 들어와도 홈 폴더까지만. 거기서 root를 또 따야 하는데(→ **권한 상승/Privilege Escalation**), 그 단계에서 막히는 공격이 많다
3. **평소 일반 계정 사용 = 그 자체가 방어**. 칼리도 예전엔 root 기본이었다가 지금은 일반 계정을 기본값으로 바꿨다

## 관련 명령어
```
$ whoami          내가 누구인지
$ id              내 사용자/그룹 ID
$ sudo 명령어      관리자 권한으로 그 명령 실행
$ su - 사용자      다른 사용자로 전환
$ passwd          내 비밀번호 변경
```

## 직접 해보기
```
$ whoami
$ id
$ cat /etc/passwd       시스템 계정 목록 (여기서 사용자 구조 구경)
$ sudo ls /root         일반 사용자로는 못 보던 root 폴더를 sudo로 보기
```
> `/etc/passwd` 는 경로 순회 공격의 단골 타겟이다. 이 파일이 어떻게 생겼는지 눈에 익혀두면 나중에 웹 해킹 실습에서 "아 이걸 훔치는 거구나" 하고 바로 이해된다.

## 완료 기준
- root와 일반 사용자의 차이를 설명할 수 있다
- sudo가 왜 항상 root로 사는 것보다 안전한지 안다
- '권한 상승'이 뭔지 감이 온다

# 6단계 — 텍스트 다루기

## 무엇을 배우나
- 긴 파일 보기: `less`, `head`, `tail`
- 검색: `grep` (⭐ 실무 최다 사용)
- 파이프 `|` 와 리다이렉션 `>`
- 편집기: `nano` (초보용)

## 명령어

### less / head / tail — 긴 파일 보기
```
$ less 긴파일.log       스크롤하며 보기 (q로 나옴, / 로 검색)
$ head 파일.txt          앞 10줄
$ head -n 20 파일        앞 20줄
$ tail 파일.txt          뒤 10줄
$ tail -f 로그.log       실시간으로 새 줄 따라가기 (로그 감시!)
```
> `tail -f` 는 로그를 실시간 감시할 때 쓴다. 블로그 컨셉으로도 좋은 명령어.

### grep — 텍스트 검색 (⭐⭐⭐ 가장 많이 씀)
```
$ grep "찾을단어" 파일.txt
$ grep -i "단어" 파일       대소문자 무시
$ grep -r "단어" 폴더/       폴더 안 전체 검색 (recursive)
$ grep -n "단어" 파일       줄 번호까지
```

### 파이프 `|` — 명령을 연결
앞 명령의 결과를 뒤 명령의 입력으로 넘긴다.
```
$ cat /etc/passwd | grep daeul       passwd 내용 중 daeul만
$ ls -l | grep ".txt"                목록 중 txt만
$ cat 로그 | grep "error" | wc -l     error가 몇 줄인지 세기
```
> 파이프는 리눅스의 꽃이다. 작은 도구를 조합해 큰 일을 한다.

### 리다이렉션 `>` `>>` — 결과를 파일로
> 블로그에서는 #5에서 분량 때문에 빼고, **#7(로그 분석)에서 다룬다.** 로그 검색 결과를 저장하고 싶다는 필요가 생긴 뒤에 배우게 하려는 순서다. `2>/dev/null`(오류 숨기기)도 함께 다룰 예정이다.
```
$ ls -l > 목록.txt        결과를 파일에 저장 (덮어쓰기)
$ echo "메모" >> 노트.txt   파일 끝에 추가
```

### nano — 초보용 편집기
```
$ nano 파일.txt
```
- 화면 아래 단축키 안내가 뜬다
- `Ctrl+O` 저장, `Ctrl+X` 나가기
- (vim은 강력하지만 진입장벽이 높으니 나중에)

## 직접 해보기
```
$ cd ~/linux-practice
$ cat /etc/passwd > users.txt
$ less users.txt              (q로 나오기)
$ grep "root" users.txt
$ cat users.txt | grep "bash"
$ nano memo.txt              (내용 쓰고 Ctrl+O, Ctrl+X)
$ cat memo.txt
$ echo "추가 줄" >> memo.txt
$ cat memo.txt
```

## 완료 기준
- `grep` 으로 파일에서 원하는 줄을 찾을 수 있다
- 파이프 `|` 로 명령 두 개를 연결할 수 있다
- nano로 파일을 만들고 저장할 수 있다

# 7단계 — 프로세스와 패키지

## 무엇을 배우나
- 실행 중인 프로그램(프로세스) 보기·끄기
- 프로그램 설치·삭제 (apt)

## 프로세스 명령어
```
$ ps aux                실행 중인 모든 프로세스
$ ps aux | grep nginx    특정 프로그램만
$ top                   실시간 프로세스 모니터 (q로 나옴)
$ htop                  top의 예쁜 버전 (설치 필요)
$ kill PID번호           프로세스 종료
$ kill -9 PID           강제 종료
```
> PID = 프로세스 번호. `ps` 나 `top` 에서 확인한다.

## 패키지 관리 (데비안/우분투/칼리)
```
$ sudo apt update              설치 가능 목록 갱신 (설치 전 항상)
$ sudo apt upgrade             설치된 것들 업데이트
$ sudo apt install 프로그램      설치
$ sudo apt remove 프로그램       삭제
$ apt search 키워드             검색
```
> `apt update` 는 "뭘 설치할 수 있는지 목록을 새로고침"이고
> `apt upgrade` 는 "실제로 버전을 올림"이다. 헷갈리지 말 것.

## 직접 해보기
```
$ ps aux | head
$ top                    (q로 나오기)
$ sudo apt update
$ sudo apt install htop
$ htop                   (q로 나오기)
$ which htop             프로그램이 어디 설치됐는지
```

## 완료 기준
- 실행 중인 프로세스를 보고 종료할 수 있다
- apt로 프로그램을 설치/삭제할 수 있다
- update와 upgrade의 차이를 안다

# 8단계 — 네트워크 기초

## 블로그 메모
- 블로그 #9(예정). **네트워크 첫걸음 #3에서 뺀 실습**(`ip a`의 `/24`, `ip route`의 `default via` = 게이트웨이)을 여기서 한다. 네트워크 #1\~#3(IP, 서브넷 마스크, 게이트웨이, DHCP)은 이미 발행되어 링크로 연결할 수 있다.

## 무엇을 배우나
- 내 IP 확인, 연결 테스트
- 포트와 연결 상태 보기 (보안에서 핵심)
- 기초 네트워크 명령어

## 명령어
```
$ ip a                  내 IP 주소 (구버전: ifconfig)
$ ping google.com       연결 테스트 (Ctrl+C로 중단)
$ curl 주소             웹페이지 내용 가져오기
$ wget 주소             파일 다운로드
$ netstat -tulpn        열린 포트와 연결 상태 (sudo 권장)
$ ss -tulpn             netstat의 최신 버전
$ nslookup google.com   도메인 → IP 변환
$ dig google.com        더 자세한 DNS 조회
```

## 보안 관점
- **`netstat`/`ss`**: 내 시스템에 어떤 포트가 열려있는지 본다. 열린 포트 = 공격 표면. 방어의 기본.
- **`curl`**: 웹 취약점 테스트할 때 요청을 직접 날리는 데 쓴다.
- **포트 개념**: IP는 건물 주소, 포트는 그 건물의 몇 호실. 80(HTTP), 443(HTTPS), 22(SSH) 등.

## 직접 해보기
```
$ ip a
$ ping -c 4 google.com       (-c 4 = 4번만)
$ curl https://example.com
$ nslookup google.com
$ sudo ss -tulpn             내 시스템의 열린 포트 구경
```

## 완료 기준
- 내 IP를 확인할 수 있다
- 포트가 뭔지, 열린 포트가 왜 보안상 중요한지 안다
- ping으로 연결을 테스트할 수 있다

# 9단계 — SSH (원격 접속)

## 무엇을 배우나
- SSH가 뭔지, 왜 쓰는지
- 공개키/개인키 원리
- 왜 개인키는 600 권한이어야 하는지

## SSH란
**Secure Shell.** 멀리 있는 리눅스 서버에 **암호화된 통로로 접속**해서 명령을 내리는 방법. 서버 관리의 기본이고, 보안 실습에서 계속 나온다.

```
$ ssh 사용자@서버주소
$ ssh daeul@192.168.0.10
$ ssh -p 2222 daeul@서버       포트 지정
```

## 공개키/개인키 (핵심 개념)

비밀번호 접속은 위험하다(추측·무차별 대입 가능). 그래서 **키 쌍**을 쓴다.

- **공개키(public key)**: 자물쇠. 서버에 걸어둔다. 누가 봐도 됨.
- **개인키(private key)**: 열쇠. 내 컴퓨터에만 둔다. 절대 남 주면 안 됨.

자물쇠는 아무나 채울 수 있지만, 여는 열쇠는 나만 있다 → 내가 맞다는 게 증명됨.

## 키 만들고 쓰기
```
$ ssh-keygen -t ed25519          키 쌍 생성
# ~/.ssh/ 안에 id_ed25519(개인키), id_ed25519.pub(공개키) 생김

$ ls -la ~/.ssh
$ cat ~/.ssh/id_ed25519.pub       공개키 내용 (이걸 서버에 등록)

$ ssh-copy-id daeul@서버           공개키를 서버에 자동 등록
```

## 왜 개인키는 600인가
```
$ chmod 600 ~/.ssh/id_ed25519
```
개인키를 남이 읽을 수 있으면(예: 644) 훔쳐가서 나인 척 접속할 수 있다. 그래서 **주인만 읽고 쓰기(600)** 여야 한다. 권한이 헐거우면 SSH가 아예 접속을 거부한다.

> **보안 실전**: 공격자가 서버 하나를 뚫으면 거기 있는 개인키를 훔쳐 **다른 서버로 갈아탄다(측면 이동/Lateral Movement)**. 그래서 키 관리가 침투와 방어 양쪽에서 핵심이다.

## 직접 해보기
```
$ ssh-keygen -t ed25519       (계속 엔터)
$ ls -la ~/.ssh
$ cat ~/.ssh/id_ed25519.pub
$ chmod 600 ~/.ssh/id_ed25519
$ ls -l ~/.ssh/id_ed25519      권한 확인
```
> 실제 원격 접속은 TryHackMe나 OverTheWire에서 서버 주소를 주니 거기서 연습.

## 완료 기준
- SSH가 뭘 하는지 설명할 수 있다
- 공개키와 개인키의 역할 차이를 안다
- 개인키가 600 권한이어야 하는 이유를 안다

```bash
#!/bin/bash
```

```bash
done
```

```bash
#!/bin/bash
```


# 부록 B — 초보가 자주 하는 실수

1. **`rm -rf` 를 함부로 쓴다** → 삭제 전 항상 `ls` 로 확인
2. **문제 생기면 `chmod 777`** → 보안 구멍. 정확한 권한을 준다
3. **root로 상시 로그인** → 일반 계정 + 필요할 때 sudo
4. **Tab 자동완성을 안 쓴다** → 오타·시간 낭비. Tab을 습관화
5. **에러 메시지를 안 읽는다** → 리눅스 에러는 대부분 친절하다. 읽으면 답이 있다
6. **복붙만 하고 손으로 안 친다** → 안 남는다. 직접 타이핑
